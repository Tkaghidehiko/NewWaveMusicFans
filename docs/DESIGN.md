# NewWaveMusicFans — 設計・計画ドキュメント

> 最新の音楽情報サイトを構築・公開し、データ分析を回しながら継続的に改善・運営していくためのマスタープラン。

作成日: 2026-08-04

---

## 1. コンセプト / ポジショニング

- **一言で**: 「次世代の音楽の波」と「日本 ⇄ 海外のクロスオーバー」を追うメディア。まだブレイク前の新進アーティスト、海外の最新ムーブメント、国境を越えて注目され合う日本・海外アーティストにフォーカス。
- **サイト名との整合**: `NewWaveMusicFans`（＝新しい波の音楽ファン）とコンセプトが完全一致。
- **差別化**: 「AIによる高速な情報収集 × 運営者による編集方針とブラッシュアップ」というハイブリッド編集体制。単なる転載・翻訳サイトではなく、"次世代・越境" という独自の切り口を持つ。
- **ターゲット読者**: 新しい音楽・これから来るアーティストを人より早く知りたい音楽ファン。日本と海外の両方の動きを追いたい層。
- **なぜ勝てるか**: 「次世代の新人 × 日本と海外の相互注目」という切り口は競合が薄く、SEO・ファン化ともに有利。

### 主要カテゴリ（コンテンツの4本柱・確定）
1. **Next Wave（次世代アーティスト候補）** — 洋楽の次世代を担う新人・ブレイク前の注目株
2. **Global Trends（海外の新しい流行）** — 海外で生まれている新しいムーブメント・ジャンル・現象
3. **J → World（世界が注目する日本人アーティスト）** — 海外で評価・注目される日本アーティスト
4. **World → J（日本が注目する海外アーティスト）** — 日本で人気・注目を集める海外アーティスト

### Wave（横断セクション）
4本柱が「**どこの音楽か**」（空間の軸）なのに対し、Wave は「**いつの音楽か**」（時間の軸）を扱う。
一定期間のジャンル・アーティストの傾向を分析し、いまがどの波の上にあるのかを示す定点観測。

5つ目の柱にはしない。「海外の流行」と「今がどの波か」は排他ではなく後者が前者を含むため、
並列にすると軸が混ざる。サイト名の由来でもあり、他メディアとの差が最も出る場所と位置づける。

> 記事の置き場所の判断基準は [docs/CONTENT-MAP.md](CONTENT-MAP.md) にまとめてある。記事を書く前にそちらを見る。

## 2. コンテンツ戦略と編集パイプライン

### コンテンツの4本柱
1. **新譜・リリース情報**（API連携で半自動）
2. **ランキング・トレンド**（API連携で半自動）
3. **レビュー・コラム・特集**（AI下書き → 運営者がブラッシュアップ）
4. **アーティスト紹介・データベース**（API + 独自編集）

### AI支援 編集パイプライン（人間 in the loop）
```
[収集] AIが海外記事/動画/APIから情報を収集・要約
   ↓
[整理] 事実・出典・論点を構造化してまとめる
   ↓
[方針決定] 運営者が「どの切り口で書くか」を決定  ← ここが独自性の源泉
   ↓
[下書き生成] AIが方針に沿って日本語の独自記事を生成
   ↓
[ブラッシュアップ] 運営者が加筆・修正・ファクトチェック
   ↓
[公開] CMSから公開・SNS連携
```

### ⚠️ 著作権・コンプライアンスの原則（必読）
- 海外記事・動画は **着想と事実確認のソース** として使う。**原文の転載・逐語翻訳は不可**。
- 記事は必ず **自分の言葉で書き起こした独自コンテンツ** にする（要約は「大幅に短く・異なる表現で」）。
- **歌詞の掲載は一切しない**。ジャケット等の画像は権利を確認（公式配布素材/API提供画像/引用の範囲）。
- **出典を明記**（参照元へのリンク）。
- 情報は **一次情報での裏取り** を基本とし、誤情報を出さない。

## 2.5. デザイン方針（確定）

**方向性**: 彩度を落としたセージグリーンの背景 + カテゴリごとのアクセント。
背景を主張させないことで、カテゴリの色分けを効かせる。**青系は使わない。**

> 当初は「茶を含んだマットブラック」で始め、紺 → スレートを経てセージに移した。
> 暖色のアクセント4色と補色関係になるため、背景を明るくしてもカテゴリ色が沈まない。
> 実装が正であり、この表は `app/globals.css` の `:root` と一致していなければならない。

### カラーパレット
| 用途 | 色 |
|---|---|
| ベース背景 | `#282c24`（低彩度のセージ） |
| カード背景 | `rgba(58,64,50,.72)` / 不透明時 `#3a4032` |
| 罫線 | `#5a6150` / `#474e3e`（弱） / `#656d59`（カード） |
| 本文テキスト | `#F7EFE4` / 補助 `#d5cfc6` / 弱 `#cdc8c0` / 最弱 `#cfcac2` |
| Next Wave | `#FFD166`（ゴールド） |
| Global Trends | `#FFA845`（アンバー） |
| J → World | `#FF8A50`（オレンジ） |
| World → J | `#FF7BA0`（コーラルピンク） |
| **Wave**（横断セクション） | `#B3D3AD`（淡いセージ）— 4本柱と軸が違うことを色で示す唯一の寒色寄り |

### 背景グラデーション

`body` は 135deg の2層。下層が `#282c24` → `#434936`、上層が暖色の光のマスク（端で 0.05）。
マスク合成後の最明部は `#4a503c`。

> ⚠️ **明るくするときは、グラデーションの振れ幅を詰めること。**
> 全体を持ち上げると右下の明部も上がり、そこに載る補助テキストが 4.5:1 を割る。
> 暗部を上げつつ明部を抑える（＝幅を詰める）ことでしか両立しない。
> 現状の実測は最悪 `--text-mute` の 5.04:1。明部をこれ以上上げるなら補助テキストも上げる。

> ⚠️ **補助テキストの色を暗くしないこと。** 同じ理由で、実際に一度 2.71:1 まで落ちた。
> **階層は色差ではなく、文字サイズと太さで作る。**

### コンテンツ別のデザイン

2段構えで分ける。実装は `data-kind` / `data-category` と CSS 変数（`app/globals.css`）。

**1. レイアウトを `kind` で分ける**

| | domain（4本柱） | axis（Wave） |
|---|---|---|
| 性格 | 読み物 | 数字の分析 |
| 段の幅 | 720px | 880px |
| 行間 | 1.95 | 標準 |
| 数字 | 標準 | `tabular-nums` で縦に揃える |
| 見出し | 細い下線 | アクセント色の 2px 下線 |
| 表 | — | 2列目以降を右揃え |

**2. コンセプトを `category` で分ける（4本柱のみ）**

レイアウトは共通のまま、見出しの装飾だけが性格を表す。
同じ形だから比べられ、装飾が違うから今どこにいるか分かる。

| カテゴリ | コンセプト | 表現 |
|---|---|---|
| Next Wave | 発見 | 見出しの脇に、下から上へ伸びる線 |
| Global Trends | 波及 | 下線が左から右へ滲んで消える |
| J → World | 送り出す | 起点が左にある罫線 |
| World → J | 受け入れる | 外（右）から入ってくる罫線 |

### レイアウトのリズム
1. **ヘッダー** — グラデーションロゴ + カテゴリナビ。Wave は区切り線で分ける
2. **ヒーロー**（派手）— グラデーション背景の大きなカード、CTA ボタン2つ
3. **カテゴリ**（シンプル）— 細い縦線（2px）+ テキストのみ。ここで一度視覚的に呼吸を置く
4. **Wave**（別枠）— 4本柱の下に一段下げた囲み枠。形が違うので色に頼らず区別できる
5. **最新記事**（派手）— グラデーションのサムネ枠付きカード

> 意図: 全面を派手にするより、カテゴリで静けさを挟むことでヒーローが引き立つ。

## 3. 技術スタック（推奨構成）

| 領域 | 推奨 | 理由 |
|---|---|---|
| フレームワーク | **Next.js (App Router)** | SEOに強い、ISRで鮮度を保てる、Vercel即デプロイ |
| ホスティング | **Vercel** | Next.jsと親和性最高、無料枠あり、分析連携も容易 |
| コンテンツ管理 | **Sanity**（ヘッドレスCMS）or リポジトリ内 **MDX** | 記事の編集UIが必要ならSanity、軽量ならMDX |
| データベース | **Supabase (Postgres)** | 収集データ・記事メタデータ・分析データを保管 |
| AI | **Claude API** | 収集・要約・下書き生成のパイプライン |
| 分析 | **Vercel Analytics + Plausible/GA4** | アクセス・行動分析 |
| SNS連携 | X / Instagram 等の投稿自動化（後期） | 集客 |

> スモールスタート案: 初期はCMSを省いて **MDX + Next.js + Vercel** の最小構成で立ち上げ、記事運用が回り始めてからSanity等を導入する、が最もコスパが良い。

## 5. アーキテクチャ概要

```
[収集バッチ] (Claude API + 各種API/スクレイピング)
      │  定期実行（cron/Vercel Cron）
      ▼
[Supabase] 収集データ・記事ドラフト・メタデータ
      │
      ▼
[編集: 運営者 + AI] 方針決定・ブラッシュアップ
      │
      ▼
[CMS/MDX] → [Next.js (ISR)] → [Vercel 公開]
      │
      ▼
[分析: Vercel Analytics / Plausible] → 改善サイクルへ
```

## 6. 分析・改善ループ（運営フェーズ）

- **計測指標(KPI)**: PV、UU、直帰率、滞在時間、人気記事、流入元（検索/SNS）、検索キーワード。
- **改善サイクル（週次/月次）**:
  1. 数字を見る（どの記事・切り口が伸びたか）
  2. 仮説（伸びた要因/落ちた要因）
  3. 施策（テーマ選定・タイトル・内部リンク・投稿頻度の調整）
  4. 実行 → 再計測
- AIに分析レポートを定期生成させ、運営者が意思決定に使う。

#### 法務ページの方針
- **記載内容は「現時点で実際に行っていること」に限定する。** 実態のない取得項目を先に書かない
- ユーザー登録・マヤ暦診断を実装する際は、両ページの改定が公開の条件になる
  （各ページ末尾に改定予定として明記済み）
- アクセス解析ツールを差し替え・追加した場合もプライバシーポリシーの更新が必要
- GA4を追加する場合は、Cookieの使用と米国への越境移転の記載が追加で必要になる

#### SEOの実装メモ
- 公開URLは `lib/site.ts` で一元管理。`NEXT_PUBLIC_SITE_URL` → Vercelの自動URL → localhost の順に解決する
- OGP画像は `next/og` で自動生成（カテゴリ色でブランディング）。
  **同梱フォントが欧文のみのため、画像に載せる文字は英字に限定している**
- 日本語のタイトルは `og:title` に載せる（SNS側がテキストとして表示するため画像に載せる必要がない）
- Next.js は `openGraph` をページ単位で置換し継承しないため、`buildSocialMetadata()` を通して組み立てる
