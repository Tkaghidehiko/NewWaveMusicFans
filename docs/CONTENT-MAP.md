# 記事の構成マップ

> このサイトに何を書き、どこに置くのか。記事を書く前にここを見る。

更新: 2026-08-04

---

## 1. 3つの軸

記事の置き場所は、性質の違う3つの軸で決まります。混同すると分類が破綻するため、
それぞれが何を表すのかを先に固定します。

| 軸 | 問い | 実体 | URL |
|---|---|---|---|
| **カテゴリ** | どこの音楽か（空間） | 4本柱 | `/next-wave` など |
| **Wave** | いつの音楽か（時間） | 横断セクション | `/wave` |
| **連載** | どう書くか（形式） | サブカテゴリ | `/next-wave/check-in` など |

**カテゴリと Wave は並列ではありません。** Wave は4本柱を横断して「現在地」を示すもので、
「海外の流行（Global Trends）」と「今がどの波か（Wave）」は排他ではなく、後者が前者を含みます。
5つ目の柱にすると軸が混ざるため、別枠にしています。

コード上は `lib/categories.ts` の `kind` で区別しています（`domain` / `axis`）。
デザイン上も、4本柱が暖色なのに対し Wave だけ寒色にすることで軸の違いを示しています。

## 2. カテゴリ（どこの音楽か）

サイトの4本柱です。`docs/DESIGN.md` で確定済み。

| カテゴリ | 扱うもの | 判断基準 |
|---|---|---|
| **Next Wave** | 洋楽の次世代・ブレイク前 | まだ日本で広く知られていない海外アーティスト |
| **Global Trends** | 海外で生まれている新しい流行 | アーティスト個人ではなく、現象・ジャンル・動き |
| **J → World** | 世界が注目する日本のアーティスト | 日本発 → 海外で評価された事例 |
| **World → J** | 日本が注目する海外アーティスト | 海外発 → 日本で定着した事例 |

### 迷ったときの切り分け

- **アーティスト単体の話か、現象の話か** → 単体なら Next Wave、現象なら Global Trends
- **方向はどちらか** → 日本発なら J → World、海外発なら World → J
- **時間軸の話になっているか** → それは Wave

## 3. Wave（いつの音楽か）

一定期間のデータをまとめて見て、**いま自分がどの波の上にいるのか**を確かめるセクションです。
サイト名の由来でもあり、他メディアとの差が最も出る場所と位置づけています。

### 扱うもの
- 一定期間の注目ジャンル・アーティストの傾向分析
- いまの流行が、どの波のどのあたりに位置するのか
- 過去の波との比較（何年周期で何が戻ってきているか）

### 扱わないもの
- 個別アーティストの紹介（それは4本柱へ）
- 単発のニュース（波の話にならない）

### 運用方針
**定点観測として継続することに価値があります。** 単発では「そういう分析もある」で終わりますが、
半年ごとに同じ視点で書き続けると、過去の見立てが当たったかを検証できるようになります。

- 頻度: **半年に1回**（上半期・通年のデータが出るタイミング）
- 各回の末尾に、次回の検証対象となる「見立て」を明示して残す
- 数字は必ず出典を示す。業界レポート（Luminate、IFPI など）を軸にする

## 4. 連載（どう書くか）

カテゴリが「何について書くか」なのに対し、連載は「どう書くか」を表します。
同じカテゴリでも形式が違えば読み方が違うため、読者が形式で選べるようにしています。

記事のフロントマターの `series` で指定します。**任意**なので、単発記事も成立します。

### 実装済み — Next Wave

| slug | 連載名 | 扱うもの |
|---|---|---|
| `check-in` | 答え合わせ | 過去の予想・リストを時間を置いて検証する |
| `before-japan` | 上陸前 | 日本でまだ観る機会のないアーティスト |
| `deep-dive` | 深掘り | 1組に絞って掘り下げる |

### 検討中 — 他カテゴリ

**記事が貯まってから作ります。** 空の連載ページが並ぶと、読者にとっても検索エンジンに
とっても中身のないページが増えるだけになるため、先に器を用意しない方針です。

| カテゴリ | 連載案 | 扱うもの |
|---|---|---|
| Global Trends | 発生源 | その流行がどこから来たかを遡る |
| Global Trends | 数字で見る | チャート・ストリーミングの動きから読む |
| J → World | 突破の瞬間 | 何がきっかけで海外に届いたのか |
| J → World | 現地の受け止め | 海外メディア・リスナーの反応 |
| World → J | 定着の経緯 | 日本で受け入れられるまでに何があったか |

目安として、**そのカテゴリに同じ形式の記事が3本たまった時点**で連載化を検討します。

## 5. アーティストページ

記事とは別に、アーティスト単位のページを持ちます（`/artists/[slug]`）。

- 記事の `artists` に slug を書くと自動で紐づきます
- **この紐付けが、将来のアーティストブック機能の土台**です（`docs/FEATURES-USER.md`）
- 記事を書いたら、登場アーティストのデータも `content/artists/` に追加する

書き方は `content/README.md` を参照。`name` はラテン文字表記、日本語名は `nameJa` に入れます
（OGP画像の生成に欧文フォントしか使えないため）。

## 6. 記事を書くときの流れ

`docs/DESIGN.md` の編集パイプラインに沿った実際の手順です。

```
1. [収集] 材料を集める（AI・API・海外メディア）
2. [整理] 事実と出典を構造化する
3. [方針決定] どの切り口で書くかを決める          ← 運営者。独自性の源泉
4. [配置決定] このマップを見て、どこに置くかを決める  ← カテゴリ / Wave / 連載
5. [下書き] 記事を書く
6. [裏取り] 複数ソースで一致した事実だけを残す
7. [公開]
```

### 事実確認の方針
- **複数の独立したソースで一致した事実のみを書く**
- 単一ソースの情報は、書くなら発言者・媒体を本文中に明示する
- 数字（チャート順位・再生回数）は特に慎重に扱う
- 裏が取れなかった点は書かず、別途記録に残す

### 守ること（`docs/DESIGN.md` より）
- 参照元の転載・逐語翻訳をしない。必ず自分の言葉で書く
- 歌詞は掲載しない
- `sources` は必ず記入する（構造化データの `citation` に入ります）
